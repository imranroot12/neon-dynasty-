# Build 75 — Current Engine Publication Contract

Build 75 aligns the release gate with the current Stake Engine publication format.

For each published mode, `index.json` maps:

- `name`
- `cost`
- `events` → compressed `.jsonl.zst` game logic
- `weights` → lookup CSV

Each game-logic row must contain:

- integer `id`
- ordered `events`
- `payoutMultiplier`

The lookup CSV contains:

- simulation ID
- probability/selection weight
- payout multiplier

The payout multiplier must exactly match between the game-logic row and lookup row.

The Engine documentation states that these static files are used by RGS to select a
simulation and return its ordered events to the frontend.

## Build 75 rule

Do not treat a locally generated or historical publication set as fresh official
evidence. The final publication set must be generated by the official Math SDK run
used for release, then uploaded to Engine.

The Web SDK build must be generated from the exact Web SDK revision recorded by CI.
